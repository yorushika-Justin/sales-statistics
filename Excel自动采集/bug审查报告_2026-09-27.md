## 二、实测锤实的问题（附复现结果）

### BUG-A 🔴 高危｜静态/图片文件不存在 → 服务崩溃
- **位置**：`server.js` `serveFile()` — `fs.createReadStream(filePath).pipe(res)` 无 `error` 监听
- **机理**：文件不存在/被移走时流发出 `error`，无监听 → 未捕获异常 → **Node 进程直接退出**
- **复现**：`GET /no_such_file.png` → 服务立刻死掉（实测「无法连接到远程服务器」）
- **影响**：浏览器误请求一个不存在的资源、缩略图文件被移动后点开，都会把整个界面服务干掉；双击 bat 的用户会看到窗口闪退且无提示
- **修复**：流加错误处理，404 返回（约 3 行）

### BUG-B 🟠 中危｜非法日历日被接受，静默跑错日期
- **位置**：`server.js` `startTask()` 只校验正则 `^\d{4}-\d{2}-\d{2}$` 和「不晚于今天」；`collect.js` 的回退策略会吞掉非法日历日
- **机理**：`2026-02-30` 通过正则 → 母本 `new Date('2026-02-30')` 滚动成 3-2 → 校验不过 → **静默回退成「查昨天」**
- **复现**：`POST /api/run {"date":"2026-02-30"}` → `ok:true`，实际查询的是 `2026-09-26`（昨天）
- **影响**：请求日期与实际查询日期不一致且无任何提示，结果归属错日（界面日期控件本身拦得住，但 API 直调/未来扩展会踩）
- **修复**：server 端做与母本一致的日历日校验（`Date` 往返一致才放行）

## 三、代码审查发现（未实测，理论/边缘）

### BUG-C 🟠 中危｜`runExport` 的 download 等待 Promise 可能未被消费
- **位置**：`collect.js` — `const dlPromise = page.waitForEvent('download',…).catch(e => { throw … })`，若 `page.click('#btnExport')` 先抛错则不会 `await dlPromise`
- **机理**：30 秒后该 Promise 拒绝且无人消费 → `UnhandledPromiseRejection`（Node 15+ 默认崩溃）
- **缓解**：主流程 `catch` 会立刻 `process.exit(1)`，多半死在超时之前；但取消/竞态场景理论可触发
- **修复**：给 dlPromise 附空 catch 或重构为 `try/finally`

### BUG-D 🟡 低危｜任务起始行不广播
- `startTask` 把「—— 开始采集任务 ——」push 进 `lines` 但没 `broadcast('log')`，SSE 首屏要刷新才看得到
- **修复**：补一行 `broadcast('log', …)`

### BUG-E 🟡 低危｜退出清理的异步竞态
- `server.js` 清理钩子 `exec(taskkill…)` 后 `process.exit(1)`：Windows 下 `CreateProcess` 在 `exec()` 调用内已发出，taskkill 独立进程通常仍会执行，但**时序无保证**
- **修复**：清理路径改 `execSync`（一次性、确定性）

### BUG-F 🟡 低危｜config 启动时快照
- `server.js` 只在启动时读 `config.json`，运行中改配置（门店关键字、输出目录）需重启服务才生效
- **修复**：文档注明即可（或 `/api/status` 每次重读）
