## 1. 需求还原

1. 在现有母本基础上做一个**新的模式**——美化图形界面（不是 cmd 黑窗口）
2. 可以在界面上**选择具体日期**执行查询（不再只有"查昨天"）
3. 母本完整保留（现有 `一键采集.bat` 命令行模式不受影响）
4. 本文件只做技术分析与方案，**确认后再实施**

## 2. 现状基线

| 项 | 现状 |
|---|---|
| 母本流程 | Playwright+Edge 自动登录（OCR 验证码）→ 查询 → 导出 Excel → 调 `销售汇总.exe` → 双 PNG |
| 日期策略 | `config.date_offset`（今天 − N，默认查昨天），**无任意日期参数** → 需小扩展 |

| 已知约束 | 入口文件名 ASCII；配置 UTF-8；同步子进程调用为刻意取舍 |

## 3. 技术路线对比

| 路线 | 美观度 | 日期控件 | 开发成本 | 与现有技术栈 | 可维护性 | 结论 |
|---|---|---|---|---|---|---|
| **A. 本地网页**（Node 内置 http + 单页 HTML） | 高（现代网页任意美化） | 原生 `input[type=date]` | 低 | **完全一致**（采集就是 Node） | 好 | ✅ **推荐** |
| B. tkinter（Python 窗口） | 差（控件陈旧） | 依赖 tkcalendar，体验一般 | 中 | 割裂：采集是 Node，要跨语言调用回传进度 | 差 | ❌ |
| C. PowerShell WinForms/WPF | 中 | 可做 | 中 | 割裂，界面脚本难维护 | 差 | ❌ |
| D. Electron / Tauri 独立桌面应用 | 高 | 好 | 高（打包体积大、构建链复杂） | 割裂 | 中 | ❌ 过重 |
| E. HTA（旧式网页应用） | 低 | 差 | 低 | — | 差 | ❌ 已过时 |

**推荐路线 A** 的核心理由：
- 采集核心就是 Node/Playwright，界面用本地网页与它**同进程技术栈**，进度直传零成本
- 美化上限最高（HTML/CSS 随便做），日期控件浏览器原生就有
- **零新增依赖**（Node 内置 `http`/`fs`/`child_process`），不引入新的 npm 包
- 天然支持以后扩展（历史记录、多日期、PNG 在线预览）

### 4.3 与母本的衔接（关键决策）

**母本默认行为零变化**，仅增加一个**可选**命令行参数：

```
node collect.js                    # 老行为：查今天 − date_offset（默认昨天）
node collect.js --date 2026-09-25  # 新模式：查指定日期（界面版用）
```

- 实现方式：`collect.js` 入口处解析 `argv`，有 `--date` 则用该日期，否则走原 `config.date_offset` 路径
- 进度回传：`server.js` 用 `child_process.spawn` 启动母本，逐行读取 stdout，SSE 推给页面（母本日志已带时间戳，直接展示）
- 备选（**不推荐**）：界面版复制一份核心逻辑——两份代码必然漂移，维护成本翻倍

## 8. 实现细化（外部深度分析，经评估采纳）

> 来源：针对路线 A 的底层交互补充分析（进程/编码/协议/参数/路由/UX）。
> 评估结论：**6 块中 5 块直接采纳，3 处细节与母本实际行为不符，已纠正**（见 8.2）。

### 8.1 采纳清单

| 项 | 决定 | 要点 |
|---|---|---|
| 进程树清理 | ✅ 采纳 | 取消/退出一律 `taskkill /pid <pid> /T /F` 按树杀（Windows 下 `child.kill()` 会漏 Edge/汇总 exe，产生孤儿）；server 自身 SIGINT/exit 钩子同样清理 |
| stdout 行缓冲 | ✅ 采纳（编码处理修正） | 见 8.2-② |
| 阶段状态机 | ✅ 采纳（关键字修正） | 见 8.2-③ |
| SSE + 单任务互斥 | ✅ 采纳 | 内存单飞锁 `activeTask`（同时只允许一个采集任务）；事件类型 `log` / `stage` / `finish` / `error` |
| `--date` 参数解析 | ✅ 采纳 | 正则 `^\d{4}-\d{2}-\d{2}$` 强校验，非法回退 `date_offset` 策略；另加**不得晚于今天**校验 |
| 路径防护与成果接口 | ✅ 采纳 | `path.normalize` + 白名单根目录（`png_dir` / `excel_dir` / `logs`）；`POST /api/open-folder` → `explorer /select,"<路径>"`；`GET /api/asset` 供 PNG 缩略图/大图 |
| 启动 UX | ✅ 采纳 | 端口 `EADDRINUSE` 自增；浏览器唤起用 `start "" "<url>"` 带引号；前端刷新后 `GET /api/status` 重挂 SSE + 拉日志缓存，不丢运行现场 |

### 8.2 三处纠正（与细化文本的差异，以母本实测行为为准）

1. **「汇总 exe 的 GBK 乱码污染 stdout」不成立**：母本 `runSummary` 用 `execFileSync` 且不透传 stdio，`销售汇总.exe` 的输出根本不会进入 collect.js 的 stdout 管道。界面解析的只有 collect.js 自身 `log()` 的 UTF-8 文本，**无需转码层**。
2. **多字节截断**：细化文本的 `chunk.toString('utf8')` 在汉字跨 chunk 时会花字。改为 `child.stdout.setEncoding('utf8')`（Node 内置 StringDecoder 自动拼接半截多字节）+ 行缓冲分割。
3. **阶段关键字必须对母本真实日志**（原文的"执行查询/开始拉取/下载 Excel/生成图片"在母本中不存在，照抄指示灯不亮）。映射表：

| 界面阶段 | 触发关键字（母本实际输出） |
|---|---|
| 登录中 | `登录尝试` / `验证码识别` / `登录成功` / `会话有效` |
| 查询中 | `查询日期` / `门店:` / `查询结果` |
| 导出中 | `Excel 已保存` / `Excel 校验` |
| 汇总中 | `调用销售汇总` / `调用汇总脚本` / `汇总完成` |
| 完成 | `全部成功` |
| 失败 | `【失败】` |

### 8.3 成果物结构化提取（finish 事件 payload）

从母本日志行解析，不加侵入式协议：

| 字段 | 来源日志行 |
|---|---|
| 条数 | `查询结果: N 条` |
| 合计金额 | 合计行 `合计: N条 179.00 2141.71` 的末段 |
| Excel 路径 | `Excel 已保存: <路径>` |
| PNG 路径 | `PNG 品牌汇总: <路径>` / `PNG 品名明细: <路径>` |
| 耗时 | `全部成功，耗时 N 秒` |
