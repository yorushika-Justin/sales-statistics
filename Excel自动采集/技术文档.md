## 1. 这是什么

双击一个 `.bat`，全自动完成：

**登录思迅供应商平台（验证码自动识别）→ 查询前一天「供应商日销售汇总」（羊森东门里店）→ 导出 Excel 到 `D:\Program Files (x86)` → 自动调用 `dist\销售汇总.exe` → 双 PNG 输出到 `D:\16678\相册\销售额\<日期>\` 并自动弹开品牌汇总图**

典型耗时约 15~20 秒（热会话免登录约 15 秒）。

## 2. 使用方法

### 日常使用（推荐：桌面图标）
1. 双击桌面 **「销售一键采集」** 图标（蓝底"汇"字）
2. 看黑窗口跑完（自动弹出品牌汇总 PNG 即成功）
3. 任意键关窗

### 开始菜单磁贴
开始菜单程序列表已有「销售一键采集」，右键 → **固定到"开始"屏幕** 即成磁贴（Win10 不允许程序自动钉磁贴，这一步需手动，仅首次）。图标含 16~256 六档尺寸，磁贴/任务栏显示清晰。

### 也可直接跑
- 双击 `Excel自动采集\一键采集.bat`
- 或命令行 `node collect.js`（可加 `--date YYYY-MM-DD` 查指定日期）

### 图形界面版（v2.0：日采集 + 月度采集）
- 双击桌面 **「销售采集界面」**（或 `Excel自动采集\图形界面版\启动界面.bat`）
- 浏览器打开美化界面，主区两张卡片：
  - 左「日采集」：日期选择 → 开始采集 → 实时进度 → 结果（条数/合计/PNG 预览）
  - 右「月度采集」（**v2.0 新增**）：选年月 →「查询总销量」/「自由点总销量」
    - 「查询总销量」：整个月的品牌汇总，**只出 1 张图**，标题 `2026年9月总销量`
    - 「自由点总销量」：该品牌整月品名明细，**只出 1 张图**，第二列是门店名称，标题 `2026年9月自由点总销量`
    - 区间规则：已满月 = 月初第一天~月末最后一天；本月未满 = 月初第一天~昨天；本月 1 号 → 提示"本月暂无可查数据"；未来月份选不了
    - 输出：`D:\16678\相册\销售额\2026-09\2026-09_总销量.png` 与 `2026-09_自由点明细.png`
    - 与日采集共用同一把单飞锁：三个任务互斥，同时只会跑一个
- **单实例（v1.5）**：已经有一个界面在跑时，再双击只会把那个界面打开一次并直接退出（退出码 0），**不会再起第二个服务**——两个界面同时采集会往同一张 `<日期>.png` 里写，可能留下被覆盖/半张的图
- 详见 `图形界面版\技术评估与方案.md`

### 成功时你会看到
- Excel：`D:\Program Files (x86)\供应商日销售汇总_<运行日期>_<时分秒>.xls`
- PNG：`D:\16678\相册\销售额\<查询日期>\<查询日期>.png` + `<查询日期>_品名.png`
- 月度 PNG（图形界面版 v2.0）：`D:\16678\相册\销售额\<YYYY-MM>\<YYYY-MM>_总销量.png` 与 `<YYYY-MM>_<品牌>明细.png`

### 常见失败提示
| 提示 | 含义 | 怎么办 |
|---|---|---|
| 查询 0 行：昨天数据可能尚未同步 | 供应商系统还没出昨天的数 | 稍后重跑即可 |
| 登录失败（已重试 5 次） | 验证码一直识别错或密码改了 | 看 `logs\` 里的截图；确认 `config.json` 密码 |
| 门店校验失败 | 条件记忆丢了，没选到羊森东门里店 | 用 `headless:false` 跑一次人工选店后重试 |
| 缺依赖: xxx | 环境缺失（Edge/Python/目录） | 按提示补齐 |

## 4. 技术方案（为什么是这个样子）

```
Playwright + 本机 Edge（不另下浏览器，headless）
 ├─ 登录：填表 → 拦截 /Handlers/VerifyCode.ashx 服务端原图字节
 │        → Python rapidocr 识别（截图版识别率低，原图稳定）
 │        → POST /api/Account/Login（页面自己的 JS 提交）
 ├─ 查询：/Online/Supplier/RptSale.aspx?menuId=6.4.1
 │        easyui datebox 用 jQuery API 设值：datebox('setValue', ...)
 │        门店取自「条件记忆」，校验含 store_keyword
 ├─ 导出：点 #btnExport → Playwright download 事件 → saveAs(excel_dir)
 └─ 汇总：execFileSync(dist\销售汇总.exe, [xls])
          断言 png_dir\<日期>\ 双 PNG 存在
```

**为什么不用纯 HTTP 爬取**：实测 `/api/Account/Login` 在验证码通过后固定 500（纯 HTTP 模拟的黑盒问题），换成真实浏览器由页面自己的 JS 提交后一次通过。

**为什么 OCR 用服务端原图**：页面上的验证码截图带缩放/噪点，rapidocr 识别不出；拦截 `VerifyCode.ashx` 的原始 PNG 字节后识别稳定（本批测试全对）。

## 5. 配置 `config.json`

```json
{
  "user": "<供应商平台账号>",
  "password": "<供应商平台密码>",
  "store_keyword": "羊森东门里店",
  "excel_dir": "D:\\Program Files (x86)",
  "png_dir": "D:\\16678\\相册\\销售额",
  "summary_mode": "exe",
  "summary_exe": "..\\dist\\销售汇总.exe",
  "python": "D:\\Python\\python.exe",
  "headless": true,
  "login_retry": 5,
  "date_offset": 1,
  "edge_path": ""
}
```

| 字段 | 说明 |
|---|---|
| `user` / `password` | 供应商账号密码（日志不打印密码） |
| `store_keyword` | 门店校验关键字（必须能在门店字段值里找到） |
| `excel_dir` | Excel 落盘目录 |
| `png_dir` | 仅用于完成后核验 PNG 落点（实际输出由汇总脚本内置目录决定）。**v1.5 起预检会读取 `..\汇总脚本.py` 的 `OUTPUT_DIR` 与之比对，不一致时在日志打 `[WARN]` 提醒（不阻断）**；若两侧不一致，请以汇总脚本的实际输出目录为准 |
| `summary_mode` | `exe`（默认）或 `py`（排错用，见下） |
| `python` | OCR 用的 Python（需已装 rapidocr-onnxruntime） |
| `headless` | `false` 时弹出浏览器窗口观察过程 |
| `login_retry` | 验证码/登录失败最大重试次数 |
| `date_offset` | 查询日期 = 今天 − 该值；默认 1 = 昨天 |
| `edge_path` | 可选。Edge 的 msedge.exe 路径；留空则自动探测常见安装位置（64 位/32 位 Program Files） |

> **注意（BUG-F）**：图形界面版 `server.js` 在**启动时**读取本配置生成快照；运行中修改配置（门店关键字、输出目录等）需**重启服务**才生效。命令行模式每次运行都实时读取，无此限制。

### ⚠ 改配置的编码要求
**必须用 UTF-8 保存**（文本编辑器或 Node 写回）。用 PowerShell 5.1 的 `Set-Content` 默认 GBK 会把中文路径/门店名写成乱码，预检会直接报缺依赖。

### ⚠ 关于入口文件名（为什么是 `collect.js` 而不是中文名）
cmd 批处理对非 ASCII 文件名/注释的编码随系统代码页变化（GBK 与 UTF-8 互掐会打断行、路径传参变乱码）。因此 `一键采集.bat` 与主脚本文件名**刻意保持 ASCII**，所有中文提示由 `collect.js` 直接输出（Node 向控制台写 Unicode，不受代码页影响）。

### 排错模式（`summary_mode: "py"`）
汇总环节改为调 `python ..\汇总脚本.py <xls>`，控制台能看到汇总脚本的输出；其余环节完全相同。

## 6. 流程细节

1. **预检**：逐项检查依赖与目录，缺什么直接报什么，退出码 1
2. **登录**：优先复用 `_pw_state.json` 会话；失效自动走验证码登录（OCR 失败或登录失败自动刷新验证码重试 ≤ `login_retry` 次）
3. **查询**：起=止=今天−`date_offset`；门店校验不通过即报错（不自动选店）；查询结果 0 行即中止（判定数据未同步），**不导出空表**
4. **导出**：下载后用 xlrd 快速验标题/行数
5. **汇总**：调 exe（默认无窗口）；完成后断言 `png_dir\<查询日期>\` 双 PNG 存在；exe 自身会**自动弹开**品牌汇总图
6. **失败**：控制台红字 + `logs\错误_*_时间戳.png` 现场截图 + 退出码 1

> 日期一致性：查询日（昨天）= xls 内部日期 = 汇总脚本建的 `<日期>\` 子文件夹名，采集脚本只核验不重复解析。

## 7. 已知限制

1. 昨天数据未同步 → 0 行中止，需人工重跑（无定时重试）
2. `config.json` 密码明文（本地文件）
3. 依赖：本机 Edge、Node.js、`D:\Python`（含 rapidocr）、`dist\销售汇总.exe`
4. 汇总环节若报错，exe 会弹 tkinter 错误框需人工关掉（采集侧 120 秒超时兜底）
5. 固定单店（羊森东门里店）；日期支持"单日"与"整月"（v2.0）。多店/自动选店仍未支持
6. **月度采集（v2.0）不主动设置平台上的门店条件**：只读取并校验它是不是羊森东门里店（校验不过就明确报错，不会静默出错数据）。若哪天在平台页面把门店改成了别的店，需要先在平台上选回羊森东门里店再跑
7. **月度采集固定走 Python**（`month_summary.py`）：打包的 `dist\销售汇总.exe` 是旧版本、不含月度函数；日采集仍按 `config.json` 的 `summary_mode` 走 exe
8. 供应商网站改版（URL/控件 id 变化）时，改 `collect.js` 顶部常量区
9. **刻意取舍**：密码明文存 `config.json`（本机使用场景，如要加密属 v2）；OCR/汇总用同步子进程调用（这些阶段内无并发页面交互，实测不影响 Playwright 通信）
