## 1. 目标

双击一个 `.bat`，全自动完成：

1. 登录思迅商旗供应商平台（验证码自动识别）
2. 查询「供应商日销售汇总」：**日期 = 前一天**、**门店 = [1001]羊森东门里店**
3. 导出 Excel → **Excel 下载目录**（`D:\Program Files (x86)`）
4. 自动调用本项目封装好的汇总脚本 → 生成 2 张 PNG → **销售额输出目录**（`D:\16678\相册\销售额\<日期>\`）

一条命令、无人值守；任何一步失败都有明确提示 + 日志 + 现场截图。

## 2. 已验证事实（2026-09-27 实测）

| # | 结论 | 依据 |
|---|---|---|
| 1 | 纯 HTTP 模拟登录**不可行**：验证码通过后服务端固定 500 | `step1` 试跑，参数格式已排除 |
| 2 | 必须用**真实浏览器**驱动（Playwright + 本机 Edge，无需另下浏览器） | `step1_login.js` 一次登录成功 |
| 3 | 验证码用**服务端原图字节** OCR（rapidocr）识别稳定；页面截图版识别失败 | 原图 786B → `5566` 正确 |
| 4 | 报表页是 easyui，日期可用 JS API 直接设值：`jQuery(datebox).datebox('setValue', ...)` | `step4` 设起=止=昨天成功 |
| 5 | 门店由「条件记忆」自动带出 `[1001]羊森东门里店`，脚本需**校验**而非盲信 | `step4` 读到该值 |
| 6 | 查询结果 57 条 / 179.00 / **2141.71**，与手动操作截图完全一致 | `step4` 输出 |
| 7 | 导出下载可精确落盘任意路径（`download.saveAs`），文件名由服务端生成 | 落到本目录 39,424 字节 |
| 8 | 导出的 xls 与手动导出同源同结构，`xlrd` 可读（64 行，标题/日期/门店齐全） | 内容抽样验证 |
| 9 | 汇总脚本 `main(带参数)`：出 2 张 PNG 到 `OUTPUT_DIR\<日期>\`，并**自动弹开**品牌汇总图 | 源码 `main()` 段 |

## 5. 配置文件 `config.json`

键名沿用 `网页端-2/config.json` 的英文风格：

```json
{
  "user": "<供应商平台账号>",
  "password": "<供应商平台密码>",
  "store_keyword": "羊森东门里店",
  "excel_dir": "D:\\Program Files (x86)",
  "png_dir": "D:\\16678\\相册\\销售额",
  "summary_mode": "exe",
  "summary_exe": "..\\dist\\销售汇总.exe",
  "python": "D:\\Python\\python.exe",
  "headless": true,
  "login_retry": 5,
  "date_offset": 1
}
```

| 字段 | 说明 |
|---|---|
| `user` / `password` | 供应商账号密码（明文存本地，日志中不打印） |
| `store_keyword` | 门店校验关键字，须能在门店字段值中找到 |
| `excel_dir` | 阶段3 导出 Excel 的落盘目录 |
| `png_dir` | 期望的 PNG 输出目录，**仅用于完成后断言核验**；实际输出由汇总脚本内置 `OUTPUT_DIR` 决定（两者应一致，不一致时告警） |
| `summary_mode` | `exe`=调 `dist\销售汇总.exe`（默认，即"封装好的"）；`py`=调 `python 汇总脚本.py`（排错用，日志更透明） |
| `summary_exe` | 相对本目录的 exe 路径 |
| `python` | OCR 用的 Python 解释器（需含 rapidocr） |
| `headless` | `true` 静默跑；`false` 弹出浏览器窗口便于观察调试 |
| `login_retry` | 验证码识别/登录失败的最大重试次数 |
| `date_offset` | 查询日期 = 今天 − 该值，默认 1（昨天）；实测空数据分支时可临时改为 -1 查未来日期 |

## 6. 详细流程与异常分支

### 阶段0 预检
- 检查：`config.json` 可解析、`node_modules` 存在、Edge 可执行文件存在、`python` 存在、`excel_dir` / `png_dir` 存在
- 任一缺失 → 控制台明确提示缺什么，退出码 1（不弹无意义的错）

### 阶段1 登录
1. 若 `_pw_state.json` 存在 → 带会话直接打开报表页试探；被弹回登录页/看到 `#UserName` → 会话失效，走 2
2. 打开 `OnlineLogin.aspx?r=supplier` → 填账号密码
3. 监听 `VerifyCode.ashx` 响应拿**原图字节** → rapidocr 识别
4. 识别结果为空或长度 ≠4 → 重刷验证码（点 `#imgCode`）重识
5. 提交登录；收到验证码错误弹窗（A012）→ 自动刷新重试，**≤ `login_retry` 次**
6. 落到 `OnlineMain.aspx` → 成功，保存会话

### 阶段2 查询
1. 打开 `/Online/Supplier/RptSale.aspx?menuId=6.4.1`
2. 日期：起 = 止 = **昨天**（运行日 −1）。依据：手动习惯"今天查前一天"，试跑设起=止=昨天与手动结果 57 条完全一致
3. 门店：读门店字段值，**必须包含** `store_keyword`；不包含 → 报错退出（v1 不做自动选店，避免复杂度，列 v2 可选）
4. 点 `#btnQuery` → 轮询数据行数，超时 30s 仍未出数
5. **0 行** → 判定"昨天数据尚未同步"，中止并提示稍后重跑（不导出空表，避免污染汇总）

### 阶段3 导出
1. 点 `#btnExport` → 捕获 `download` 事件（30s 超时）
2. `saveAs(excel_dir + 服务端文件名)`（文件名含时分秒，天然不撞名）
3. 落盘后用 xlrd 快速验前 3 行（标题/日期）再进入阶段4

### 阶段4 汇总
1. `summary_mode=exe` → `"dist\销售汇总.exe" "<xls完整路径>"`（无控制台窗口）；`py` → `python 汇总脚本.py "<xls>"`（继承控制台输出）
2. 断言 `png_dir\<提取日期>\` 下出现 `<日期>.png` 与 `<日期>_品名.png`
3. 汇总脚本自带行为保留：**自动弹开品牌汇总图**（跑完即见结果）
4. 汇总失败：错误详情在 Excel 同目录的 `汇总错误.log`（脚本既有约定），采集日志中指出该路径

> 日期一致性设计：阶段2 查询日（昨天）→ xls 内部 Row 日期 → 汇总脚本自行提取并建 `<日期>\` 子文件夹。采集脚本**不重复解析日期**做输出，只做核验。

## 8. 已知限制

1. **数据滞后**：供应商系统前一天数据若未同步 → 查询 0 行 → 中止，需人工重跑
2. **密码明文**：`config.json` 本地明文（与需求给到的方式一致）；日志不记录密码
3. **环境依赖**：本机 Edge、Node.js、`D:\Python`（rapidocr）——预检阶段逐项校验
4. **页面改版风险**：选择器/URL 变更会失效 → 所有关键常量（URL、按钮 id、门店字段）集中在 `collect.js` 顶部常量区，改版时一处修改
5. **范围锁定**：固定"单日（昨天）单店（羊森东门里店）"；多店/多日属 v2 扩展
6. **会话时效未知**：失效表现即被弹回登录页，已由阶段1步骤1兜底自动重登
