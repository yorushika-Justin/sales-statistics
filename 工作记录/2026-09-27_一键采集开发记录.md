## 三、经验沉淀

1. **纯 HTTP 模拟不可行**：该供应商系统登录接口在验证码通过后有黑盒 500，自动化一律走真浏览器（Playwright）最稳
2. **验证码 OCR 要拿服务端原图**：`/Handlers/VerifyCode.ashx?guid=` 的原始字节直接喂 rapidocr；不要截页面元素图（缩放+噪点识别不出）
3. **编码双坑**：① PowerShell `Set-Content` 默认 GBK，改写 `config.json` 会把 `销售汇总.exe`、`羊森东门里店` 写成乱码（预检拦下）——改 JSON 配置一律用 UTF-8；② bat/主脚本用中文文件名时，cmd 按系统代码页解析，GBK/UTF-8 互掐会打断行、路径传参变乱码——**入口 bat 与脚本名保持 ASCII**（`collect.js`），中文提示由 Node 输出（TTY 写 Unicode 不受代码页影响）
4. **easyui 控件用页面自己的 jQuery API 设值**最省事：`jQuery(input.datebox-f).datebox('setValue', 'YYYY-MM-DD')`
5. **空数据快速判定**：合计行出现但没有"N条"计数 → 连续 3 次轮询即可判定 0 行，不必等满 30 秒超时
6. 导出的 xls 与手动导出同源同结构，可直接喂既有 `汇总脚本.py` / `销售汇总.exe`，日期提取规则（Row 日期 → `<日期>\` 子文件夹）无需任何改动

## 五、外部审查回合（Gemini 审查报告处置）

Gemini 对全部交付物给出 12 项缺陷报告。逐条核实结论：**9 项采纳、2 项判定夸大/不改、1 项已知取舍**。

采纳修复（v1.2）：
1. **BUG-01 查询判据死锁**（真 bug）：原"合计行文本必须变化"在同条件重跑/条件记忆自动加载时永不成立 → 误报 0 行。改为 **EasyUI 加载遮罩 `.datagrid-mask` 为主证据 + 3 秒宽限期 + 条数出现即完成**（同条件同结果是合法成功）。注：Gemini 给的修复代码直接删防 stale，会引入吃旧数据风险，实际实现为混合方案
2. **BUG-02 PNG 假阳性**（最危险）：同日重跑时历史 PNG 会掩盖汇总失败 → `verifyPngs` 核对 `mtime ≥ 任务启动时间`，区分"不存在/历史陈旧"
3. BUG-03 验证码严格 4 位 + 去空白（对齐设计文档）
4. BUG-04 Excel 校验失败即拦截（0 字节/行数异常不入汇总）
5. BUG-05 Ctrl+C/SIGINT 清理 Edge，防无头孤儿进程
6. BUG-07 登录弹窗快速失败（2.5 秒探测弹窗，不再硬等 10 秒）
7. BUG-08 Edge 64/32 位多路径探测 + `config.edge_path` 可覆盖
8. BUG-09 预检加深 `import rapidocr_onnxruntime, xlrd`
9. BUG-11 验证码临时图用完即删；BUG-12 bat 缺 Node 提示 + 图标脚本字体多候选

未采纳：
- **BUG-06**（execFileSync 阻塞事件循环"破坏 CDP"）：夸大。这些同步调用期间无页面交互，Playwright 连接不会断；改 async 收益低
- **BUG-10**（密码加密）：已知取舍，本机使用场景；DPAPI 属 v2

回归：正常链路 14 秒 ✅｜空数据分支 2 秒中止 ✅（新判据下均正常）
