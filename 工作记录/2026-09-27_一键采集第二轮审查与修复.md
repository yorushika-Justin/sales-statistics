### 2.6 `图形界面版\server.js` 追加：单实例检测（M-3，2026-09-27 追加，经用户确认）

- **动机**：双击两次 `启动界面.bat` 会起两个服务、两个采集任务，写同一张 `<日期>.png` → 可能留下半张/被覆盖的成品，而两边都报成功。
- **修法**：`/api/status` 的 `statusPayload()` 增加身份字段 `app: 'sales-collect-gui'`；启动时先 `probeExistingInstance(BASE_PORT)`（1.5s 超时 GET `/api/status`），**只有应答方带该标记**才判定"已有本程序实例在跑" → 打印提示、按 `--no-open` 决定是否打开该地址、`process.exit(0)`（退出码 0，bat 不会误判为失败）；否则照原逻辑走端口避让监听。
- **为什么先探测 `BASE_PORT` 而不是"遍历已占端口"**：小端口才是本程序实际用的；若 5270 在别人手里、本程序在 5271，第二次双击会先让位到 5272 —— 端口避让本身能保证"两个实例不同端口"，双写风险极低；遍历探测反而会把非本程序的服务误认。
- **实测（三个场景，全部通过）**：

| 场景 | 期望 | 实测 |
|---|---|---|
| 首次启动 | 正常监听 5270 且带 `app` 标记 | ✅ 横幅正确；`/api/status` 含 `"app":"sales-collect-gui"`；5271 未被占用 |
| 第二个实例 | 识别到已有实例、只提示、不启动新服务、退出码 0 | ✅ 打印"已检测到正在运行的实例: http://127.0.0.1:5270 / 本次不再启动新服务"；退出码 **0**；原实例存活；**没有新起 5271** |
| 5270 被**非本程序**占用 | 不得误判，应让位 5271 | ✅ 输出"端口 5270 被占用，尝试 5271"并成功在 5271 提供服务 |

- **回归**：真实 Edge 打开界面 → 标题正常、**前端 JS 报错 0 条**、首屏门店/日期/按钮状态正常；测后 5270/5271 均释放、无残留进程。
- **给用户的实际变化**：以后连点两次图标，第二次只会把已有界面打开一次，不再出现"两个窗口各跑一个任务"。

## 六、给后来者的三条提醒

1. **`explorer.exe` 成功时也返回退出码 1**——`/api/open-folder` 的回调必须继续吞掉；**不要给它加错误日志**，否则"成功打开文件夹"会被记成失败。
2. **不要再给 `decodeURIComponent` / `new URL` 加新的裸调用**——它们已经踩过两次坑（`%E4%` 与 absolute-form 请求行），任何新解析逻辑都要落在 `handleRequest` 的兜底里。
3. **汇总脚本的"静默模式"靠环境变量 `SUMMARY_NO_UI=1` 显式开启**，不要改成 `isatty()` 判断：本机实测在 PowerShell 终端里 `isatty()` 也可能是 False，改回去会让"手敲命令想看到错误框"或"双击 exe"的用户失去提示（这一坑本轮已经踩过一次并回退，原因记在 §2.2）。
