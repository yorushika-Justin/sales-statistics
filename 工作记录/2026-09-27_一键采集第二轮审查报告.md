## 二、高危问题（附实测证据）

### H-1 🔴 一个畸形 URL 就让整个界面服务退出

- **位置**：`图形界面版\server.js:252`
  ```js
  const pathname = decodeURIComponent(u.pathname);   // 无 try/catch
  ```
- **机理**：`decodeURIComponent` 遇到非法百分号转义会抛 `URIError`。该调用发生在 `http.createServer` 的 **async 回调**里、任何 try 之外 → 变成未捕获异常 → Node 进程直接退出（完整堆栈见下）。
- **实测复现**（隔离区实例，`node server.js --no-open`）：
  ```
  GET http://127.0.0.1:5270/%E4%
  → 连接被拒（服务已死）

  stderr:
  D:\...\图形界面版\server.js:252
    const pathname = decodeURIComponent(u.pathname);
  URIError: URI malformed
      at decodeURIComponent (<anonymous>)
      at Server.<anonymous> (...\server.js:252:20)
  Node.js v25.9.0
  ```
  复现后 `/api/status` 返回 `ECONNREFUSED`，无 node 进程残留。
- **用户可见后果**：界面版黑窗口闪退/消失，浏览器页面失联；若当场有采集任务，任务随之被丢弃。用户只会看到"窗口没了"，没有任何提示。
- **触发难度**：不高。任何来源（书签、手输 URL、页面里带字面 `%` 的链接、其它程序拼 URL）都会命中。
- **最小修复方向**：`decodeURIComponent` 包 try/catch，失败返回 400；或整体把请求处理体包一层 try/catch 兜底。

### H-2 🔴 界面状态可以被"钉死"，且与服务端真实状态脱节

两条**已实测**的独立触发路径，后果都是"界面显示的和实际发生的不一致"，而采集是无人值守场景，用户只会看界面。

#### H-2a SSE 断线重连不补发，界面永远停在"运行中…"

- **位置**：`public\app.js:98-128`（`connectSSE`，只挂 `log/stage/finish/error` 监听，无重连补偿）、`public\app.js:170-178`（`/api/status` 只在首次加载调一次）、`server.js:275`（新客户端接入时不回放快照）
- **实测**：
  ```
  连接A 收到: log,stage,stage,log,stage,log
  --- 断开 SSE（模拟网络抖动/服务短暂不可达）---
  服务端真实状态: stage=done running=false
  --- 重连后 3 秒内收到的事件: （无）
  >>> 断线期间的 finish/error 是否补发 => 无补发
  ```
- **后果**：断线期间任务完成 → 重连后页面**没有**"任务完成"、没有结果卡、按钮仍禁用、状态胶囊仍是"运行中…"。而服务端其实已经成功、Excel 与 PNG 都已落盘。用户会以为卡死了，去点"取消"（此时服务端返回"当前没有运行中的任务"，界面又只把这句追加到日志，状态依旧不恢复）。
- **与第一轮的关系**：第一轮只验证了"**刷新页面**能重挂 SSE + 拉 logs 缓存"，那是 `init()` 路径，确实有效；但**不刷新页面时的自动重连路径没有补偿**，第一轮未覆盖。
- **最小修复方向**：`es.onopen` 里重新 `fetch('/api/status')` 并按结果重绘（或服务端在客户端接入时先推一帧 status 快照）。

#### H-2b `/api/run` 被拒时界面不回落到"运行中"，与实际状态相反

- **位置**：`public\app.js:137-149`（点开始 → 立刻 `setRunningUI(true)`；`/api/run` 返回 `!ok` 时只做 `setRunningUI(false)` + 写入日志）
- **实测**（真实浏览器驱动隔离版界面）：
  ```
  [运行中]  {startDisabled:true,  cancelHidden:false, pill:"登录中"}
  --- 强制解除禁用后连点两次开始（等价于两个页面/两个实例同时提交）---
  [连击后] {startDisabled:false, cancelHidden:true, pill:"失败",
            logTail:"启动失败: 已有采集任务在运行中"}
  ```
- **后果**：服务端**确实有一个任务在跑**（第二次请求被 409 拒绝），但界面显示"失败"、按钮可点、取消按钮隐藏 → 用户以为啥都没发生，再点一次又被拒。任务跑完的 `finish` 事件虽然还会推给这个连接，但用户的认知已经错位。
- **最小修复方向**：`!res.ok` 时先 `fetch('/api/status')`，按服务端 `running/stage` 决定 UI（服务端已经把原因写在返回里了）。

## 三、中危问题

### M-1 🟠 端口避让时打印**错误端口**，并会"多打一段启动横幅"

- **位置**：`server.js:320-341`（`listenWithRetry` 用 `server.once('error', ...)` 重新 `listen(port+1)`，但成功回调里用的仍是外层 `port`）
- **实测**（先用占位程序锁住 5270，再起实例）：
  ```
  端口 5270 被占用，尝试 5271 ...
  ==========================================
    销售一键采集 · 图形界面版
    已启动: http://127.0.0.1:5270      ← 错！实际监听的是 5271
  ==========================================
  ==========================================
    销售一键采集 · 图形界面版
    已启动: http://127.0.0.1:5271
  ==========================================
  实际监听探测: 5270 可连接: True（占位程序）, 5271 可连接: True（本服务）, 5272: False
  ```
  两条问题：① 打印了**两段**启动横幅（`server.once('error')` 每次重试都挂一个新的，旧回调未清理）；② 第一段横幅的端口是**错的**。
- **后果**：若 5270 被**别的程序**占用，用户手输/log 里看到的 `5270` 会打开别人家的服务；`--no-open` 关闭时这个错端口还会被 `exec("start ...")` 真的打开。当前实例占用 5270 的场景下（现状）只是刷屏，属"埋着的坑"。
- **最小修复方向**：把 `listenWithRetry` 的监听器在重试前 `server.removeAllListeners('error')`，并把回调改为 `() => onListening(port)` 传参闭包。

### M-2 🟠 `png_dir` 语义是"核验目录"，但与实际输出目录无绑定校验 → 陈旧 PNG 可绕过核验

- **位置**：`config.json`（`png_dir`）/ `collect.js:371-385`（`verifyPngs`）对照 `汇总脚本.py:60`（`OUTPUT_DIR = r"D:\16678\相册\销售额"` 硬编码）
- **机理**：真正决定 PNG 落点的是**汇总脚本里的硬编码 `OUTPUT_DIR`**，`png_dir` 只是"我以为它会写到哪"。
  - 若把 `png_dir` 改成别处 → `verifyPngs` 报"PNG 核验失败"，失败原因看起来像汇总出错，实际只是配置与实际输出不一致（**误导排查方向**）。
  - 反之**更危险的一种组合**：`png_dir` 保持默认、而汇总脚本的 `OUTPUT_DIR` 被改走 → 采集侧会去旧目录核验，**命中上一次的旧 PNG**…此时 `mtime >= 任务启动时间` 这道防线恰好能拦住（第一轮的 BUG-02 修复在这里救了场）。
  - 但存在**真实泄漏窗口**：`mtime` 判据是 `>= t0`，凡是**本次任务启动之后**写入的文件都算数——如果同一 `<日期>` 目录被另一个进程/另一次运行（例如你手工双击 exe 跑一次汇总）写过，本次核验就会通过。属"判据不区分写入者"的固有弱点。
- **最小修复方向**：启动时读一次 `汇总脚本.py` 的 `OUTPUT_DIR`（或让汇总脚本把实际落点回写日志/返回码），与 `png_dir` 不一致时**预检期直接告警**，而不是等核验失败。

### M-3 🟠 没有单实例锁：双击两次 = 两个服务 + 两个任务 + 两份日志互相交错

- **位置**：`server.js`（无互斥文件/无端口已占即自退逻辑）+ `启动界面.bat`（每次双击都起一个新 node）
- **实测**：连起两个实例 → 实例 1 占 5270、实例 2 退让到 **5271**，两者 `status` 都可用、各自独立 `activeTask`；两个采集进程会同时跑，**共享** `config.json`、`_pw_state.json`、`_pw_captcha_run.png`、`logs\采集日志_*.txt`。
- **后果**：两个浏览器标签、两套进度、两套取消按钮，用户分不清哪个是哪个；日志同文件追加且 `appendFileSync` 非原子，并发写有交错风险。
- **最小修复方向**：启动时先探测 `BASE_PORT` 是否已被"本程序"占用（如请求 `/api/status` 返回自家指纹），是则直接打开该地址并退出；或在目录里加 pid/lock 文件。
