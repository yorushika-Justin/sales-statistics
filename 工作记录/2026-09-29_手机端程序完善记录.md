## 二、本轮修了什么

### 2.1 A 组 — 会咬到使用者的

| 编号 | 问题 | 修法 |
|---|---|---|
| **P-1** | `<input type="file">` 选完不重置 `value` → **手机上同一个文件选第二次完全没反应** | `change` 回调里先取出文件、随即 `e.target.value = ''` |
| **P-2** | 结果区 `appendChild` 只追加不替换 → 连传两次新旧两组图叠在一起 | 状态区与结果区拆开，每次上传先清空结果区 |
| **P-3** | 超 10MB 时 Flask 返回 **HTML 错误页**，前端 `.json()` 崩 → 页面显示 `Unexpected token '<'` | 服务端加 `errorhandler(413)` 等返回 JSON；前端**先取 text 再尝试 parse**，失败给中文兜底文案 |
| **P-4** | 出错只回 `类型: 消息`，完整堆栈只在服务器 `/tmp` → **看不到在哪一行**（8-02 排查就卡在这） | 响应带 `detail`（`文件:行号(函数) → 异常`）与 `error_id`，服务器日志打同一 `error_id`；前端加「查看详情」折叠区 |
| **P-5** | 文案写死"将文件**拖入**此处"（手机没法拖）；小屏边距偏大 | 触屏（`maxTouchPoints` / `pointer: coarse`）改文案为「点击选择文件」，拖拽事件仅在非触屏绑定；加 `@media (max-width:480px)` |
| **P-6** | Render 免费层冷启动约 30 秒，页面**毫无提示**，像卡死 | 页面加载即 ping `/health`，2.5 秒未就绪显示「服务器正在唤醒…」，就绪即撤；上传期间再显示已等待秒数 |

### 2.5 独立复核发现并修复（R 组）

改完初版后派了一名**只读独立复核员**（不共享本次上下文，独立读代码 + 用 Flask test client 实测 + 核对 PyPI）。它抓到 **1 个我自己引入的高危回归** 和一批真问题，全部已修：

| 编号 | 严重度 | 问题 | 修法 |
|---|---|---|---|
| **R-1** | **高（本轮引入的回归）** | P-12 给图片加了 **24 小时强缓存**，而图片 URL 按日期固定命名（`/download/<日期>/<日期>.png`）→ **同一天重新上传后 URL 不变**，浏览器 24 小时内不请求也不重校验 → 手机看到、存进相册的都是**旧图**。而 P-1 刚让"同一文件可重复选"变得可用，两者叠加恰好制造"重传后发现没变化"的错觉 | `/download` 改为**协商缓存**：`Cache-Control: no-cache, private` + ETag。每次向服务器校验，内容未变返回 **304**（照样省流量），变了立刻拿到新图 |
| **R-2** | 中 | `hmac.compare_digest` 对含**非 ASCII 的 str** 会抛 `TypeError` → **中文口令**会让 `/?k=中文` 与 `/auth` 表单**双双 500**（未授权者即可触发） | 抽出 `_safe_eq()` 统一先 `encode('utf-8')` 再比较；三处调用点全部替换。**注意：第一次只改了两处，靠专项测试才抓出 `/auth` 里漏改的那一处** |
| **R-3** | 低 | `?k=` 通过后的 302 **丢掉其它查询参数** → `/download/x.png?k=..&dl=1` 跳转后变成内联打开而非下载 | 重定向时保留除 `k` 外的全部参数（`urlencode`） |
| **R-4** | 中 | `detail` 取的是 traceback **最内层帧**，实测指向 xlrd 内部的 `book.py:1272 (bof_error)`，对定位毫无意义，与设计初衷不符 | 改为优先取**属于本项目**的最内层帧。修复后同一场景实测为 `汇总脚本.py:306 (read_xls)` ✅ |
| **R-5** | 低 | P-15c 只改了 `web_server.py`，适配层日志时间戳仍是 UTC → 同一个日志文件里混着相差 8 小时的两种时间 | 适配层统一 `datetime.now(CST)` |
| **R-6** | 低 | 只锁了 4 个顶层包，而 P-7/P-12 依赖的恰恰是 Werkzeug 的 `send_file` / `cache_control` 行为 | `requirements.txt` 扩到 **10 个包全锁**（补 Werkzeug / Jinja2 / itsdangerous / click / blinker / MarkupSafe），并验证它们在 x86_64 Linux 上都有 wheel |
| **R-7** | 低 | 绘制中途失败会留下**残缺 PNG**，`/history` 只按 `.png` 后缀枚举，会把它当正常结果列出并可下载 | 品牌图/品名图失败时清理残留（`_remove_quietly`）；品名路径改为"**画成功才赋值**"而非先赋值再画 |
| **R-8** | 低 | "统一 JSON"漏了 405（400/404/413/500 都已是 JSON） | 补 `errorhandler(400)` 与 `errorhandler(405)` |
| **R-9** | 低 | GET `/auth` 未授权返回 200，而 `/` 返回 401，仅日志视角不一致 | 统一 401 |
| **R-10** | 低 | 弱口令无任何提醒 | 启动时若 `ACCESS_TOKEN` 少于 16 位打印警告 |
| **R-11** | 部署前置 | `render.yaml` 没有 `ACCESS_TOKEN`；若靠面板手工加，Blueprint 同步可能清掉 | `render.yaml` 补该变量并标 `sync: false`（由面板手动填写，Blueprint 不覆盖） |

**复核核实为正确、无需改动的关键项**（它逐条验证后确认）：根目录 `汇总脚本.py` 本轮确实没动过；P-8 成立（`draw_table`/`draw_table_detail` 是**调用时**读模块级 `FONT_PATH`，不存在默认参数绑定陷阱，竞态真消除）；v1.0 的 7 个返回字段一个不少、`?dl=1` 语义不变；路径校验、上传落盘、Cookie 属性、口令拦截**均无绕过**，安全面未发现严重漏洞。

**复核提出的遗留低危（本轮有意不修，已在文档声明）**：无口令失败速率限制；Cookie 是口令的确定性 sha256 派生值（泄露即长期凭证，故要求长口令）；`?k=` 会把口令写进访问日志（页面提示语保留此用法，但 302 已把口令从地址栏摘掉）；`detail` 会外露内部文件名与行号（自用可接受）；zip-bomb 型 xlsx 在全局锁下会阻塞请求。

## 四、已知限制（不修，但要知道）

1. **Render 免费层磁盘是临时的** —— 重新部署或容器重启后 `/history` 清空。这是**本次部署周期内的历史**，不是长期存档。
2. **冷启动约 30 秒** —— 免费层 15 分钟不活跃即休眠。
   - ⚠️ **诚实说明 P-6 的边界**：横幅是在页面 HTML **加载完成之后**才 ping `/health`，所以它解决的是"页面**已经打开**后服务变得不可达"（停留超 15 分钟容器睡了、网络切换、服务重启）—— 这条已实测有效。
   - 但对**首次打开**无效：容器休眠时用户等的 30 秒正是首屏 HTML 本身，此时 JS 还没跑，没有任何页面可以显示提示。
   - **真正消除首次白屏要靠保活**：用任意免费 uptime 监控（如 UptimeRobot）每 5 分钟 GET 一次 `/health`，容器就不会休眠。注意 Render 免费层是 **750 实例小时/月**，单服务 24/7 约需 730 小时，刚好够（余量很小）。
3. **口令未设速率限制** —— 若启用口令，请用足够长的随机串（**建议 20 位以上**），不要用 `123456` 这种。程序启动时对少于 16 位的口令会打印警告。
4. **并发写同名文件已加锁串行化** —— 代价是多人同时上传会排队；单用户无影响。
5. **图片走协商缓存而非强缓存** —— 每次看图会向服务器校验一次（未变返回 304）。这是刻意的：图片 URL 按日期固定命名，强缓存会导致同一天重传后一直看到旧图（R-1 的教训）。
6. **`detail` 会外露内部文件名与行号** —— 自用场景可接受；若将来多人共用，需收敛错误信息。

## 五、部署

- 线上原基线提交：`37a1275`
- 部署方式：`git push` → Render 自动重新部署（约 2-3 分钟）
- 回滚：`git revert` 后在 Render 面板 Deploy latest commit
- **部署后需要手动做一步**：在 Render 面板 → Environment 添加 `ACCESS_TOKEN`（自定义口令）→ 保存并重新部署，口令保护才生效。**不添加则该功能保持关闭，服务行为与旧版一致。**
