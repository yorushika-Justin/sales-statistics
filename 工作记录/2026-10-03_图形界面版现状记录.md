# 图形界面版现状记录（月度采集改动前基线）

- 记录日期：2026-10-03
- 用途：新增「月度总销量 / 自由点总销量」两种模式**之前**的现状快照，以后排查问题拿它对照。
- 范围：`Excel自动采集\` + `Excel自动采集\图形界面版\` + 三端共用的 `汇总脚本.py`。

## 一、整体链路（当前只有"日采集"一种模式）

```
开始菜单磁贴「销售采集界面」
  → Excel自动采集\图形界面版\启动界面.bat   （cd 到脚本所在目录 → node server.js）
  → 本地服务 127.0.0.1:5270（端口被占则自动递增）
  → 浏览器打开界面 public\index.html
  → 点「开始采集」→ POST /api/run { date }
  → spawn(node, [collect.js, '--date', <date>])   （cwd = Excel自动采集\）
  → collect.js：登录 → 查询 → 导出 xls → 调汇总脚本 → 核验 PNG
  → 界面经 SSE /api/stream 滚动日志 + 阶段条（登录 / 查询 / 导出 / 汇总 / 完成）
```

关键：**磁贴指向的是 `启动界面.bat`，bat 里只有 `node server.js`**。只要不改启动方式和端口，磁贴就一直有效。

## 三、日采集关键判据（出问题先按这几条对）

1. **会话**：`_pw_state.json` 有效则免登录直通；失效走 `doLogin()`（验证码识别，失败按 `login_retry`=5 重试）。登录失败会截图 `错误_登录_*.png`。
2. **查询页**：`RptSale.aspx?menuId=6.4.1`（供应商日销售汇总）。日期用 easyui `datebox('setValue')` 把起止两框设成同一天；门店校验 `input.textbox-value` 里必须含 `store_keyword`，否则直接失败（防"条件记忆"没勾上导致查错店）。
3. **完成判据**：datagrid 遮罩 `.datagrid-mask` 出现即认定"查询已执行"（遮罩一闪看不到时，点击后 3 秒兜底）；合计行必须匹配 `(\d+)\s*条`；0 条 → `NO_DATA`。
4. **导出**：监听 download 事件 → 存到 `cfg.excel_dir`；随后用 `python + xlrd` 交叉断言**行数 / 标题 / 日期行 / 门店行**。日期行不含本次查询日期 → 拦截（防站点回传别的日期区间）；导出行数 < 查询条数+2 → 拦截（疑似只导出了当前页）。
5. **汇总**：`SUMMARY_NO_UI=1` + `PYTHONIOENCODING=utf-8`；当前 `summary_mode="exe"` → 调 `..\dist\销售汇总.exe`（`py` 模式则调 `汇总脚本.py`）。
6. **PNG 核验**：必须是**本次任务启动后**新生成的（`mtime ≥ 任务启动时间`），防历史文件假阳性。路径 = `png_dir\<日期>\<日期>.png`（品牌汇总）+ `<日期>_品名.png`（品名明细）。

## 四、已知坑 / 注意事项

- `date_offset=1` 只作用于"没传 `--date`"的情况；界面版永远显式传日期。
- 汇总脚本的日期规则：取 xls 内部 Row2 的结束日期 **减 1 天**（当天数据不完整）；起止相同则直接取当天。
- 汇总脚本的 `OUTPUT_DIR` 是**硬编码**的，`config.png_dir` 只是"核验目录"。两者不一致时 `preflight()` 只告警，最终会在核验阶段误报"汇总失败"。
- **单飞锁**：同一时刻只允许一个采集任务；冲突时 `/api/run` 返回 409。
- `/api/open-folder` 只放行白名单目录（`png_dir` / `excel_dir` / `logs`）；`explorer.exe` 正常退出码就是 1，回调必须吞掉。
- 静态文件只从 `public\` 白名单取，路径含 `..` 直接 403。
- 服务端静态文件 `serveFile()` 已改 `Cache-Control: no-cache`（防同日重传拿到旧图）。
- **三端共用 `汇总脚本.py`**：网页端（Flask 5000）、程序端（Render 云）、exe 都依赖它 —— 改它必须保证旧函数行为一字不变。
- 图片查看器（2026-09-29 加）依赖 `public\app.js` 里的 `viewer` IIFE 与 `style.css` 的 `.viewer*`，改前端时别碰坏。

## 七、探测结论（2026-10-03 实测，月度采集开工前）

1. **"商品销售汇总查询"页 = `/Online/Supplier/RptSaleSum.aspx`**（左侧菜单"报表查询"下）。列头：行号/门店名称/国际条码/品名/品牌名称/销售数量/规格/销售金额；控件结构与日汇总页同源（2 个 `input.datebox-f` 日期框、`input.textbox-f[flag="Id"]` 条件框、`#btnQuery`/`#btnExport`）。**实测"品牌"为空时查询返回 0 行**（门店为空反而能跨门店查），所以它不能作为"全品牌总销量"的数据源。
2. **"供应商日销售汇总"页（`RptSale.aspx?menuId=6.4.1`）支持整月区间**：把两个日期框设成 `2026-09-01` / `2026-09-30` 即得整月数据（实测 1331 行、合计 2721.00 / 35902.14，导出 1338 行 / 14 列，含日期、门店名称、规格、库存）。
3. **本地聚合与平台口径逐位一致**（关键依据）：整月导出里过滤"品牌名称=自由点"再按品名聚合 = 37 行 / 1546 / 17435.8699，与"商品销售汇总查询"页导出的自由点文件完全相同；品牌汇总 22 个品牌 / 35902.1399 也与导出文件合计行一致。
4. **不要用 `textbox('setValue')` 直接改平台的门店/品牌条件框**：实测改完查询返回 0 行（服务端不认这个值）。门店/品牌应当用弹窗选择（`input.textbox-f[flag="Id"]` 后面的 `a.textbox-button` → "门店选择"/"请选择品牌"窗口 → 点行回填）。月度采集最终选择**不碰这两个框**，只设日期 + 保留门店校验。
5. **条件记忆会覆盖页面初始值**：页面加载时会从服务端恢复上次的日期/门店/品牌（`#cacheCondition` 默认勾选），所以每次采集都必须显式设置日期区间。
6. 导出文件的抬头行**随条件变化**：勾了门店才有 `门店机构：[1001]羊森东门里店` 行；末行是 `合计：<N> 条 / <数量> / <金额>`。
