# 月度总销量采集 · 工作计划（2026-10-03）

> **状态：已全部完成（2026-10-03）**。实际执行与验证结果见 `工作记录\2026-10-03_月度总销量采集_记录.md`，
> 探测过程中修正的一处方案假设见该记录第二节第 1 条（"商品销售汇总查询"页在品牌为空时查不出全品牌数据，
> 故"月总销量"改用日汇总页的整月区间，两种模式的数据口径已核对到逐位一致）。

## 一、目标

在**图形界面版**里新增两种"月度"采集模式（原有"日采集"完全不变）：

| 模式 | 数据来源 | 查询条件 | 输出 |
|---|---|---|---|
| 月总销量 | 报表查询 → **商品销售汇总查询** | 门店=羊森东门里店，日期=月初~月末 | **1 张**品牌汇总图 |
| 自由点总销量 | 同一页面 | 再加 品牌=`[2932]自由点` | **1 张**品名明细图（**第二列=门店名称**） |

界面布局：主区改成**两个卡片** —— 左边保留现在的"日采集"（查询日期 + 门店机构 + 开始采集），右边新增"月度采集"（年/月选择 + 「查询总销量」「自由点总销量」两个按钮），门店固定显示羊森东门里店。

已确认口径：

1. 未满月 → 月初第一天 ~ **昨天**；已满月 → 月初 ~ 月末；今天正好是 1 号（区间会反向）→ 界面直接提示"本月暂无可查数据"，不发起采集；未来月份不可选。
2. 标题带年份：`2026年9月总销量` / `2026年9月自由点总销量`。
3. 落盘：`png_dir\2026-09\2026-09_总销量.png`、`2026-09_自由点明细.png`。
4. 明细图 8 列 = 行号 / **门店名称** / 国际条码 / 品名 / 品牌 / 数量 / 金额 / 库存，末尾保留合计行；月总销量图 = 现有品牌汇总样式（品牌 + 金额降序 + 总计行）。
5. 结果区在月度模式下只显示 1 张缩略图；图片查看器（放大 / 拖动 / 滚轮 / Esc）继续可用。
6. 三个任务共用现有单飞锁，互斥排队，不同时开两个浏览器。

## 二、硬约束

- **磁贴不能失效**：`启动界面.bat` → `node server.js` → 5270 端口这条链路（含 `--no-open` 等既有参数）保持原样。
- **三端不受影响**：`汇总脚本.py` 的 `read_xls` / `read_xlsx` / `read_xls_items` / `read_xlsx_items` / `draw_table` / `draw_table_detail` 对旧调用方的行为必须**一字不变**（网页端 / 程序端 / exe 都依赖它）。
- **先备份后动手**，备份到 `备份_2026-10-03_月度采集\`：
  `collect.js`、`图形界面版\server.js`、`图形界面版\public\{index.html,app.js,style.css}`、`汇总脚本.py`。

## 三、步骤

### 阶段 0 · 探路（一次性脚本，跑完即删）

现有代码只走过"供应商日销售汇总"页（`RptSale.aspx?menuId=6.4.1`），**商品销售汇总查询**页面的 URL / 控件 / 导出列结构都还没见过。先写一个临时探测脚本（参考 `step1_login.js` 的登录写法 + 复用 `_pw_state.json` 会话）：

1. 登录 → 展开左侧"报表查询"菜单 → 打开"商品销售汇总查询"页；
2. dump：页面 URL、日期控件（easyui datebox 数量与用法）、门店字段、**品牌字段的操作方式**、按钮 id、结果表与合计行结构；
3. 实导出两份样例放到 `Excel自动采集\`：① 9 月整月、不筛品牌；② 9 月整月、品牌=自由点；并打印两份文件的表头与行数；
4. 结论写进工作记录。

**若发现与假设冲突**（例如该页不能按区间导出、品牌字段无法自动化、导出列结构与预期不同）→ **停下来报告**，不硬做。

### 阶段 2 · 汇总层（`汇总脚本.py` 只加不改）

- 新增 `read_xls_items_with_store()` / `read_xlsx_items_with_store()`：在现有明细读取基础上多取一列**门店名称**（表头扫描逻辑与旧函数同源，找不到该列时返回空串，不报错）。
- `draw_table_detail()` 增加**可选参数** `stores=None`：`None` 时输出与现在**逐像素一致**；传入门店列表时在第二列插入"门店名称"列（其余列、列宽、截断、合计行规则全不变）。
- 新增 `draw_table_month(data, title, output_path)`：品牌汇总图换标题用（旧 `draw_table` 不动，内部逻辑同源）。
- 新增月度专用入口 `Excel自动采集\month_summary.py`：
  `--mode summary|brand --xls <文件> --month 2026-09 [--brand 自由点]`
  → 调上面的函数 → 输出到 `<OUTPUT_DIR>\2026-09\` 下的对应 PNG。
  月度模式**固定走 Python**，不依赖 `dist\销售汇总.exe`（exe 是旧打包，不含新函数）。
- 回归验证：用同一份样例 xls，分别用旧调用与新调用生成品牌汇总图 / 品名明细图，**逐字节比对**确认旧路径零变化。

### 阶段 3 · 采集层（`collect.js` 加分支）

新增参数：`--month 2026-09 --mode summary|brand [--brand 自由点]`。

- 日期区间计算：已满月 → 月初~月末；未满月 → 月初~昨天；区间非法直接报错（由界面先挡一层）。
- 新页面流程复用现有骨架：登录（同一套会话复用）→ 设置日期区间 → 校验门店 → （brand 模式）设置品牌 → 查询 → 导出行数校验 → 调 `month_summary.py` → **核验 1 张 PNG 是本次新生成**。
- 日志行沿用现有风格（供 `server.js` 解析阶段），月度核验日志单独一行输出 PNG 路径。
- **日模式分支（`--date`）一行不动**。

### 阶段 4 · 界面层（图形界面版）

- `server.js`：新增 `POST /api/run-month { month, mode }`，校验月份格式（`YYYY-MM`）、范围（不晚于当前月）、"本月 1 号"边界；复用 `activeTask` 单飞锁与阶段/日志广播；`handleLine` 兼容月度日志格式。
- `public\index.html` + `style.css`：主区改两卡片；

## 五、风险

| 风险 | 应对 |
|---|---|
| 商品销售汇总查询页控件无法自动化（品牌字段是弹窗选择等） | 阶段 0 探测先暴露，停下报告，不硬做 |
