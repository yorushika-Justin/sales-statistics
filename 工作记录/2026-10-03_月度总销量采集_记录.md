# 月度总销量采集 · 变更记录（2026-10-03）

改动范围：**只动图形界面版**（`Excel自动采集\` + `Excel自动采集\图形界面版\`），exe / 网页端 / 程序端行为不变（已用像素级回归坐实）。

## 一、这次加了什么

图形界面版新增两种"月度"模式，界面主区拆成两个卡片：左「日采集」（原功能）、右「月度采集」（年月选择 + 两个按钮）。

| 模式 | 按钮 | 查询区间 | 输出 |
|---|---|---|---|
| 月总销量 | 查询总销量 | 月初第一天 ~ 月末最后一天 | 只 1 张品牌汇总图，标题 `2026年9月总销量` |
| 自由点总销量 | 自由点总销量 | 同上 | 只 1 张品名明细图，标题 `2026年9月自由点总销量` |

边界规则：**本月未满 → 月初 ~ 昨天**；已满月 → 月初 ~ 月末；今天正好 1 号 → 前端/后端都直接提示"本月暂无可查数据"；未来月份不可选（前后端双重拦截）。

输出落点：`<相册销售额目录>\2026-09\2026-09_总销量.png`、`2026-09_自由点明细.png`。

明细图 8 列（对齐用户给的参照图）：**行号 / 门店名称 / 国际条码 / 品名 / 品牌名称 / 销售数量 / 规格 / 销售金额** + 合计行（数量、金额）。

## 二、探测结论（决定实现路径的关键事实）

1. **"商品销售汇总查询"页（`RptSaleSum.aspx`）不能作为"全品牌总销量"的数据源**：实测该页**品牌为空时查询返回 0 行**（门店为空反而能查，跨门店 324 条）。所以"月总销量"没法走这个页面。
2. **"供应商日销售汇总"页（`RptSale.aspx`，日采集一直用的那个）支持整月区间**：把起止日期设成 `2026-09-01` / `2026-09-30` 即可，实测 1331 条、合计 2721.00 / 35902.14，导出 1338 行、14 列（含日期、门店名称、品牌名称、规格、库存）。
3. **本地聚合与平台逐位一致**（这是选它的底气）：
   - 从整月导出里过滤 `品牌名称=自由点` → 按品名聚合 = **37 行 / 数量 1546 / 金额 17435.8699**
   - 从"商品销售汇总查询"页（品牌=自由点）导出的文件 = **37 行 / 1546 / 17435.8699**
   - 两者完全相同；品牌汇总 22 个品牌、总金额 35902.1399 也与导出文件的合计行一致。
4. 平台上**直接给门店/品牌输入框 `textbox('setValue', ...)` 不被服务端接受**（查询变 0 行）；改成弹窗选店又是多余依赖 → 结论是**不碰这两个条件框**，只设日期区间，并保留原有的"门店校验"（值里必须含 `羊森东门里店`，否则明确报错）。
5. 导出的抬头行会随条件变化：勾了门店才有 `门店机构：[1001]羊森东门里店` 行 → 校验不能假设它一定存在，但我们在采集前已强制校验门店字段。

## 五、要留意的地方

- **月度采集依赖平台"条件记忆"里的门店**：进入报表页后我们不主动改门店框，只校验它是不是 `羊森东门里店`。若哪天在平台页面上手动把门店改成了别的店（记忆会跟着变），采集会**明确报错**"门店校验失败…"，不会静默出错误数据。届时在平台页面把门店选回羊森东门里店再跑即可。
- 月度模式固定走 Python（`month_summary.py`），**不经过打包的 `销售汇总.exe`** —— exe 是旧打包，不含月度函数，也不打算重打包（日采集仍按 `config.json` 的 `summary_mode` 走）。
- 平台导出的 xls 文件名由站点决定，会落到 `config.json` 的 `excel_dir`（每月跑一次多一个文件）。
- 明细图列里**没有"库存"列、改成"规格"**：因为月度是按品名聚合的，库存没有可聚合的语义，而"规格"是商品固有属性，且与用户给的参照图完全一致。
- 仍然只有一个后台任务（单飞锁）：日采集与月度采集互斥，同时点只会有一个跑起来，另一个收到"已有采集任务在运行中"。
